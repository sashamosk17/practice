# Технологическая практика в Летней школе по программной инженерии НИУ ВШЭ

## Краткое описание

Этот README описывает выполнение технологической практики в роли ассистента Летней школы по программной инженерии (ПИ) на базе Факультета компьютерных наук НИУ ВШЭ. В ходе практики я помогал преподавателю и школьникам, готовил учебные материалы, сопровождал практические занятия, проводил консультации и участвовал в проектной работе команд.

# Материалы практики

## Краткое описание

В этом репозитории собраны материалы, подготовленные для практики. Основной акцент сделан на тестовых данных, генераторах и проверке решения, а также на шаблоне постера и инструкции по оформлению README.

## Тестовые данные

Тестовые данные подготовлены так, чтобы проверять решение на разных сценариях:

- базовые случаи с простыми входами;
- граничные случаи с минимальным и пограничным размером графа;
- случаи с несколькими маршрутами одинаковой длины;
- случаи с недостижимыми вершинами;
- более сложные входы для проверки устойчивости и скорости работы.

Описание тестовых данных нужно для того, чтобы было понятно:

- какие именно входы используются;
- что считается правильным ответом;
- какие ошибки можно поймать на каждом тесте.

## `generator.cpp`

Файл `generator.cpp` отвечает за генерацию тестовых данных.

Он нужен для того, чтобы:

- быстро создавать большое количество входных примеров;
- проверять решение не только на вручную подготовленных данных, но и на случайных сценариях;
- расширять набор тестов без ручного составления каждого файла;
- подбирать входы разного размера и сложности.

Генератор используется вместе с описанием тестов и помогает поддерживать системный подход к проверке решения.

## `dijkstra.cpp`

Файл `dijkstra.cpp` используется как проверка решения на основе алгоритма Дейкстры.

Его роль:

- сравнивать результаты решения с ожидаемым поведением;
- проверять корректность на подготовленных входных данных;
- использоваться как ориентир при анализе ошибок в тестах;
- помогать выявлять случаи, где решение работает неверно или нестабильно.

Такой файл особенно полезен, когда нужно быстро убедиться, что решение правильно обрабатывает графовые входы и находит кратчайшие пути.

## Шаблон постера в Figma

Отдельно подготовлен шаблон постера в Figma. Он нужен для итогового оформления результатов проекта.

Шаблон помогает:

- выдержать единый стиль оформления;
- структурировать результаты исследования;
- удобно разместить графики, таблицы и выводы;
- подготовить материал к защите в понятном и аккуратном виде.

## Инструкция по написанию README

В репозитории также предусмотрена инструкция по написанию README. Она задает формат итоговой документации и помогает оформить материалы последовательно и понятно.

В README обычно описываются:

- название и краткое назначение материалов;
- что находится в репозитории;
- как устроены тестовые данные и генераторы;
- зачем нужен файл проверки;
- как использовать шаблон постера и другие сопутствующие материалы.

## Итог

Все материалы в этом проекте собраны как единый комплект для проверки, оформления и сдачи практики. Основной акцент сделан на тестовых данных, автоматической генерации входов, проверке решения Дейкстрой и подготовке шаблона постера.
